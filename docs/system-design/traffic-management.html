1. 总览

流量治理总的来说：就是防止某些有问题的流量导致正常流量也受到影响，防止造成雪崩效应和连锁反应。

2. 熔断

Circuit Breaker

Resilience4j 的 Circuit Breaker 实现熔断保护，当下游故障率达到阈值时自动断开，避免级联失败。

详见 高可用设计 — Circuit Breaker

3. 隔离

通过物理或逻辑上分离资源和请求，减少单点故障的影响范围。

隔离的维度

隔离方式 说明
动静隔离 静态资源（CDN）与动态请求分离，静态故障不影响动态服务
读写隔离 读流量和写流量走不同的实例或数据源，写故障不影响读
机房隔离 多机房部署，一个机房故障不影响其他机房
线程隔离 单个微服务内，不同下游调用使用独立线程池（Bulkhead）
参考

详见 高可用设计 — Bulkhead

4. 重试

包括同步和异步重试，以及各种退避机制，帮助在失败时优雅地恢复服务。

Resilience4j Retry

Resilience4j 提供灵活的重试配置，支持退避策略。

⚠️ 注意 Retry Storm

无节制的重试会导致重试风暴（Retry Storm）— 下游本已过载，被大量重试压得更狠。务必配合指数退避和最大重试次数限制。

参考

详见 高可用设计 — Retry + Exponential Backoff + Jitter

5. 降级

自动和手动降级，作为服务负载过重时的应急措施。

  • 自动降级：系统检测到压力超过阈值时自动触发降级策略
  • 手动降级：运维人员通过开关/配置主动降级非核心功能
  • Non-CSP 数据降级：核心业务数据走主路径，非核心数据（如推荐、浏览历史）降级为默认值或空
参考

详见 高可用设计 — Graceful Degradation

6. 超时

客户端的强 Timeout 设置

客户端调用下游时，必须设置合理的超时时间，避免线程/连接被无限期占用。

Resilience4j Time Limiter

Resilience4j 提供 Time Limiter 组件，为异步操作设置超时上限，超时后自动取消并返回 fallback。

  • 设置连接超时（Connection Timeout）— 建立连接的最长等待
  • 设置读取超时（Read Timeout）— 等待响应的最长等待
  • 超时后快速失败，释放线程资源

7. 限流

客户端和服务端限流，确保系统在高负载下仍能稳定运行。

限流的层次

层次 说明
CSG 服务级限流 API 网关层对每个服务设置流量配额，防止单个服务被打爆
Global Rate Limiter 单机限流 每个实例自身限制请求速率，保护进程不被突发流量冲垮
Load Shedding API 级别限流 针对特定 API 的细粒度限流，核心 API 和非核心 API 不同配额
参考

详见 高可用设计 — Rate Limiting + Load Shedding

核心：熔断、隔离、重试、降级、超时、限流六种手段相互配合，构建多层次的流量治理体系。每个手段在不同层面（网关层、服务层、实例层、API 层）发挥作用，共同保障系统在异常流量下的稳定性。
